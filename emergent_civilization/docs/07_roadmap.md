# 07. 개발 로드맵 (Roadmap)

각 단계는 하나의 가설(→ `01`)을 검증 가능하게 만드는 것을 목표로 한다.
행동은 `IMPLEMENTED_ACTIONS` 에 추가되며, 그 전까지는 파싱은 되나 거부된다.

| **v0.1** | 생존 | move, eat, rest, idle | (기반) | ✅ 구현 |

## 현재 상태 (v0.1–v0.4 + 생태계 + 3D 시각화 + LLM 데모)

이 저장소는 substrate·대조군·거래·생태계·시각화를 구현했다:
- 세계·물질대사·행동 실행·부분 관찰·지표·틱 루프(`sim/`).
- `HeuristicPolicy`(대조군)와 `LLMPolicy`(실험군, 백엔드 교체식). LLM 백엔드:
  OpenAICompat(RunPod/NVIDIA) / Anthropic / 오프라인 Mock·Echo(`llm_client.py`).
- **거래/대화**(v0.3): `speak` + `trade`(2단계 핸드셰이크·신뢰·교환비 기록).
- **생태계**: 밤/포식자(`ecology.py`), 은신처(`build`), 도구(`craft`),
  선물·신뢰(`give`). → `docs/09_ecology.md`
- **시각화**: `snapshot.py` + `server/viz_server.py`(GET /state) +
  `viewer/village.html`(무설치 아이소메트릭, 밤·포식자·은신처·이벤트 렌더) +
  `unity/`(동일 스냅샷 3D 클라이언트, 상태바·이벤트 팝업). → `08_visualization.md`
- **LLM 데모**: `examples/run_llm_agents.py` — 관찰→프롬프트→모델→JSON 행동의
  실험 배선과 `reason`(왜 그랬는지) 로그. 오프라인 Mock 백엔드로 즉시 실행,
  env 하나로 실제 모델 전환.
- 검증: 테스트 15개 통과. 베이스라인 200틱에서 은신처 6·도구 5·선물 6·
  동맹 1·평균신뢰 0.43, 사망 5(포식자 4·기아 1). 위협 앞에서 무리·은신처·
  선물 같은 협력이 창발.

### v0.4 + 생태계 확장 (완료)
- **위협**: 밤/포식자(`ecology.py`) — 노출된 외톨이를 사냥, 무리를 지으면
  피해 반감, 은신처 안이면 무효. → 협력·주거에 **생존 유인** 부여.
- **주거**: `build`(3 wood + 1 stone) → 은신처. 포식자 차단 + 휴식 강화.
  이로써 목재·석재가 **진짜 가치**를 얻어 식량 일변도 거래 문제가 해소됨.
- **제작**: `craft`(2 wood + 1 stone) → 도구. 채집 효율 ↑ → 역할 분화(H1).
- **인간관계**: `give`(선물, 신뢰 +0.2) + 거래 성사(신뢰 +0.1). 동맹=상호
  신뢰쌍, 갈등=음의 신뢰. `metrics.alliances/mean_trust` 로 측정.
- 베이스라인 200틱: 은신처 6·도구 5·선물 6·동맹 1·평균신뢰 0.43,
  사망 5(포식자 4·기아 1) → 세계가 **위험하되 협력으로 살아남을 수 있음**.

## 다음 단계: v0.5 (가격의 자율 결정)
1. 도구·은신처로 재료 수요가 생겼으니, 재료↔식량·재료↔도구 교환비가
   시간에 따라 **수렴**하는지 측정(`price_log`, rolling std).
2. LLM 실행 대 베이스라인 대조로 "가격의 창발"(H3)을 검정.
3. 필요 시 `speak` 로 가격 흥정이 오가는지 정성 분석(`reason` 로그).

## 확장성 로드맵 (10 → 100+)

| 병목 | 대응 | 상태 |
|------|------|------|
| 틱당 N회 LLM 추론 | `Simulation(max_concurrency=N)` — 동시 요청(서버: `--llm-concurrency`). 자체 소유 엔드포인트(RunPod vLLM 등)에서만 의미 있음; 공유 무료 API는 `decision_gap`(`--llm-gap-ms`)로 순차 페이싱 | ✅ 구현 |
| 컨텍스트 토큰 폭증 | 관찰 JSON 압축 직렬화 + 시스템 지침 압축(완료); 기억 요약 계층(v0.6, 미착수) | 🟡 부분 |
| 비용 | 소형 모델 기본 + 중요 결정만 대형 모델 라우팅 | ⬜ |
| 재현성 | 모든 무작위에 시드; LLM 온도·시드 기록; 실행 로그 JSONL 보존 | 🟡 부분(시드는 완료, 로그 보존 미착수) |
| 공간 밀집 | `--size` 로 월드 크기 스케일(예: 100명 → `--size 32`) | ✅ 구현(수동 조정) |
| 이름 중복 | 18개 이름 순환 시 "Aria2" 처럼 번호 접미사 부여 | ✅ 구현 |

### 동시성 실측 (오프라인, 시뮬레이션 백엔드 지연 0.5초 가정)
- 순차(에이전트 20명, `max_concurrency=1`): 약 10.0초/틱
- 동시(에이전트 20명, `max_concurrency=20`): 약 0.5초/틱 — **약 20배**
- 100명, `max_concurrency=20`(빠른 오프라인 백엔드 기준): 3틱에 0.06초,
  스냅샷 크기 약 40KB — 페이로드·직렬화 자체는 100명 규모에서 병목이 아님.
  실제 병목은 오직 추론 서버의 응답 속도.

## 릴리스 게이트 (각 버전 승격 기준)

한 버전을 "완료"로 부르려면:
1. 새 행동에 대한 단위 테스트가 통과한다(`tests/`).
2. 오프라인(Echo/Heuristic)에서 시뮬레이션이 크래시 없이 완주한다.
3. 해당 가설의 지표가 `metrics.py` 에 배선되어 요약에 노출된다.
4. LLM 실행 1회 + 베이스라인 1회의 대조 로그가 저장된다.

## 리스크와 완화

| 리스크 | 완화 |
|--------|------|
| LLM이 형식을 안 지킴 | `parse_action` 폴백 + 재시도(향후) |
| 창발이 프롬프트 힌트의 산물 | 금지 어휘 목록(→ `05`) + 베이스라인 대조 |
| 세계가 너무 쉽거나 어려움 | 생존 상수 튜닝(→ `03`), "일부 생존" 목표 |
| 비용 폭증 | 서브샘플 결정 + 소형 모델 라우팅 |
| 재현 불가 | 전 구간 시드 + 로그 보존 |
