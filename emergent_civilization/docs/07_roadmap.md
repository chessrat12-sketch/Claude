## 현재 상태 (v0.1–v0.3 완료 + 3D 시각화)

이 저장소는 substrate·대조군·거래 계층·시각화를 구현했다:
- 세계·물질대사·행동 실행·부분 관찰·지표·틱 루프.
- `HeuristicPolicy`(대조군)와 `LLMPolicy`(실험군, 백엔드 교체식).
- **v0.3 거래/대화**: `speak`(메시지 큐) + `trade`(제안→수락/거절 2단계
  핸드셰이크, 성사 시 인벤토리 교환·상호 신뢰 +0.1·교환비 기록).
  `interactions.py` 가 in-flight 메시지/제안을 담고, 관찰에
  `incoming_messages`/`pending_offers` 로 노출된다.
- **시각화**: `sim/snapshot.py`(전역 렌더 스냅샷) + `server/viz_server.py`
  (백그라운드 틱 + `GET /state`) + `viewer/village.html`(무설치 아이소메트릭
  마을) + `unity/`(동일 스냅샷을 소비하는 3D 클라이언트). → `08_visualization.md`
- 검증: 베이스라인 200틱에서 전원 생존, 거래 6건 성사,
  **창발 교환비 나무→식량 ≈ 0.5**(어디에도 설정한 적 없음, 거래에서 읽어냄),
  지니 ≈ 0.30. 테스트 10개 통과.

### 거래에 대한 관찰 노트
동질적 베이스라인에서는 모두가 식량을 원하고 아무도 식량을 내놓지 않아
대부분의 제안이 만료된다(현실적 희소성). 소수 거래는 "식량 여유 있는
에이전트가 미래 제작(v0.4)을 대비해 재료를 사들이는" 상보적 수요에서 발생한다.
**진짜 경제 검증은 LLM 실행 대 베이스라인 대조**에서 이루어진다.

## 다음 단계: v0.4 (분업/제작) 구현 계획

1. `IMPLEMENTED_ACTIONS` 에 `craft` 추가 + 간단한 레시피(예: wood+stone→tool).
2. 제작물에 **기능적 가치** 부여(예: tool → 채집 효율 ↑). 이로써 재료가
   비로소 값을 가지며, 식량 일변도였던 거래에 진짜 상보성이 생긴다.
3. `metrics.role_specialization()` 로 채집·제작·거래 역할 분화(H1) 측정.
4. 프롬프트: `craft` 행동의 *존재*와 레시피만 알림(직업명·분업 지시 금지).

## 확장성 로드맵 (10 → 100+)

| 병목 | 대응 |
|------|------|
| 틱당 N회 LLM 추론 | 배칭·비동기 호출; 이벤트 트리거·서브샘플 결정(전원 매 틱 X) |
| 컨텍스트 토큰 폭증 | 기억 요약 계층(v0.6); 관찰 부분성 유지 |
| 비용 | 소형 모델 기본 + 중요 결정만 대형 모델 라우팅 |
| 재현성 | 모든 무작위에 시드; LLM 온도·시드 기록; 실행 로그 JSONL 보존 |
| 공간 밀집 | 100명 수용 위해 월드 크기·자원 밀도 스케일 |

## 릴리스 게이트 (각 버전 승격 기준)

한 버전을 "완료"로 부르려면:
1. 새 행동에 대한 단위 테스트가 통과한다(`tests/`).
2. 오프라인(Echo/Heuristic)에서 시뮬레이션이 크래시 없이 완주한다.
3. 해당 가설의 지표가 `metrics.py` 에 배선되어 요약에 노출된다.
4. LLM 실행 1회 + 베이스라인 1회의 대조 로그가 저장된다.

## 리스크와 완화

| 리스크 | 완화 |
|--------|------|
| LLM이 형식을 안 지킴 | `parse_action` 폴백 + 재시도(향후) |
| 창발이 프롬프트 힌트의 산물 | 금지 어휘 목록(→ `05`) + 베이스라인 대조 |
| 세계가 너무 쉽거나 어려움 | 생존 상수 튜닝(→ `03`), "일부 생존" 목표 |
| 비용 폭증 | 서브샘플 결정 + 소형 모델 라우팅 |
| 재현 불가 | 전 구간 시드 + 로그 보존 |
