# 07. 개발 로드맵 (Roadmap)

각 단계는 하나의 가설(→ `01`)을 검증 가능하게 만드는 것을 목표로 한다.
행동은 `IMPLEMENTED_ACTIONS` 에 추가되며, 그 전까지는 파싱은 되나 거부된다.

| 버전 | 목표 | 새 행동 | 검증 가설 | 상태 |
|------|------|---------|-----------|------|
| **v0.1** | 생존 | move, eat, rest, idle | (기반) | ✅ 구현 |
| **v0.2** | 채집 | gather | (기반) | ✅ 구현 |
| **v0.3** | 거래 | speak, trade | H2, H3 | ⏳ 다음 |
| **v0.4** | 분업의 자발적 형성 | craft | H1 | ⬜ |
| **v0.5** | 가격의 자율 결정 | (trade 심화) | H3 | ⬜ |
| **v0.6** | 신뢰와 평판 | (relationships 배선) | H4 | ⬜ |
| **v0.7** | 규칙·제도의 자발적 생성 | propose_rule | H5 | ⬜ |
| **v1.0** | 자율 AI 문명 | — | H1–H5 종합 | ⬜ |

## 현재 상태 (v0.1–v0.2 완료)

이 저장소는 substrate 와 대조군을 구현했다:
- 세계·물질대사·행동 실행·부분 관찰·지표·틱 루프.
- `HeuristicPolicy`(대조군)와 `LLMPolicy`(실험군, 백엔드 교체식).
- 오프라인 데모(`examples/run_v01_survival.py`)와 테스트(`tests/`)로
  **세계가 생존 가능함(solvable)**을 검증. 베이스라인에서 10명 전원이
  200틱 생존, 지니 ≈ 0.18.

## 다음 단계: v0.3 (거래) 구현 계획

1. `IMPLEMENTED_ACTIONS` 에 `speak`, `trade` 추가.
2. `ActionExecutor`:
   - `speak`: 인접 에이전트의 다음 관찰에 메시지 삽입(간단한 메시지 큐).
   - `trade`: 2단계 핸드셰이크 — 제안 → 상대 다음 턴 수락/거절. 성사 시
     인벤토리 교환 + `metrics.trades++` + 교환비를 `price_history` 에 기록.
3. `observation.py`: `incoming_messages`, `pending_offers` 필드 추가(부분 시야 유지).
4. 프롬프트: 거래·대화 행동의 *존재*만 알림(가격 예시·강요 금지).
5. 분석: 교환비 수렴 여부를 베이스라인(거래 없음)과 대조.

## 확장성 로드맵 (10 → 100+)

| 병목 | 대응 |
|------|------|
| 틱당 N회 LLM 추론 | 배칭·비동기 호출; 이벤트 트리거·서브샘플 결정(전원 매 틱 X) |
| 컨텍스트 토큰 폭증 | 기억 요약 계층(v0.6); 관찰 부분성 유지 |
| 비용 | 소형 모델 기본 + 중요 결정만 대형 모델 라우팅 |
| 재현성 | 모든 무작위에 시드; LLM 온도·시드 기록; 실행 로그 JSONL 보존 |
| 공간 밀집 | 100명 수용 위해 월드 크기·자원 밀도 스케일 |

## 릴리스 게이트 (각 버전 승격 기준)

한 버전을 "완료"로 부르려면:
1. 새 행동에 대한 단위 테스트가 통과한다(`tests/`).
2. 오프라인(Echo/Heuristic)에서 시뮬레이션이 크래시 없이 완주한다.
3. 해당 가설의 지표가 `metrics.py` 에 배선되어 요약에 노출된다.
4. LLM 실행 1회 + 베이스라인 1회의 대조 로그가 저장된다.

## 리스크와 완화

| 리스크 | 완화 |
|--------|------|
| LLM이 형식을 안 지킴 | `parse_action` 폴백 + 재시도(향후) |
| 창발이 프롬프트 힌트의 산물 | 금지 어휘 목록(→ `05`) + 베이스라인 대조 |
| 세계가 너무 쉽거나 어려움 | 생존 상수 튜닝(→ `03`), "일부 생존" 목표 |
| 비용 폭증 | 서브샘플 결정 + 소형 모델 라우팅 |
| 재현 불가 | 전 구간 시드 + 로그 보존 |
