# 06. 측정 항목 (Metrics)

측정은 `sim/metrics.py` 에서 수집한다. 지표는 4개 범주(사회 구조·경제·
사회 관계·창발)로 나뉘며, 각 지표는 대응하는 가설(→ `01`)과 마일스톤(→ `07`)을 가진다.

## 원칙: 지표는 창발을 "관찰"하지 "생성"하지 않는다

`metrics.py` 는 세계를 바꾸지 않는다. 직업·가격·동맹을 만들지 않고,
행동의 원자료에서 그 존재 여부를 *읽어낸다*. 상위 구조 카운터(trades,
rule_proposals 등)는 해당 행동이 구현되기 전부터 0으로 배선되어 있어,
마일스톤이 열리면 자동으로 채워진다.

## 1. 사회 구조

| 지표 | 정의 | 구현 |
|------|------|------|
| 역할 분화 | 에이전트별 최빈 행동 = 사실상의 "직업" | `role_specialization()` |
| 역할 엔트로피 | 역할 분포의 다양성(분업 정도) | 파생: 위 분포의 Shannon H |
| 협력 횟수 | 상호 이득 상호작용(공유·공동채집) | `action_counts` + v0.3 이벤트 |
| 거래 횟수 | 성사된 교환 수 | `trades` |

**H1 판정**: LLM 집단의 역할 엔트로피가 베이스라인 대비 유의하게 높고,
개별 에이전트의 행동 분포 분산이 크면 분업 창발로 본다.

## 2. 경제

| 지표 | 정의 | 구현 |
|------|------|------|
| 가격(교환비) | 자원쌍별 give/receive 비율 | `price_history` |
| 가격 수렴 | 교환비 분산의 시간적 감소 | 파생: rolling std |
| 자원 분포 | 세계 내 자원 총량/위치 | `world.total_resources()` |
| 부의 집중 | 인벤토리 크기의 지니계수 | `wealth_gini()` |

**H3 판정**: 무작위였던 교환비가 특정 값으로 수렴(분산 감소)하면 "가격"의
자율 형성으로 본다. 베이스라인은 거래를 안 하므로 대조가 자명하다.

> 참고: 베이스라인 v0.1 실행에서도 지니계수가 0.18 수준으로 나타난다
> (동일 정책·무작위 초기 위치만으로도 불평등 발생). 따라서 부의 집중은
> **베이스라인 대비 증가분**으로만 창발을 주장해야 한다.

## 3. 사회 관계

| 지표 | 정의 | 구현 |
|------|------|------|
| 신뢰 관계 | `relationships` 점수 분포 | Agent 상태 |
| 재거래 확률 | 신뢰 점수 대비 재상호작용 확률 | 파생: 상관 분석 |
| 동맹/갈등 | 신뢰 그래프의 군집/양극화 | 파생: 그래프 모듈러리티 |

**H4 판정**: 신뢰 점수와 재거래 확률의 양의 상관 → 평판 기반 사회 관계 형성.

## 4. 창발 현상

| 지표 | 정의 | 구현 |
|------|------|------|
| 규칙 제안 수 | `propose_rule` 발생 수 | `rule_proposals` |
| 규칙 수용률 | 제안 중 타 에이전트가 따른 비율 | v0.7 이벤트 |
| 규칙 준수율 | 수용된 규칙의 실제 준수 비율 | v0.7 이벤트 |
| 새로운 행동 패턴 | 사전 정의 없이 반복 출현한 행동 시퀀스 | 정성 + 시퀀스 마이닝 |
| 대화량 | `speak` 발생 수 | `messages` |

**H5 판정**: 규칙 제안이 발생하고 수용·준수까지 이어지면 제도의 자발적 생성으로 본다.

## 요약 리포트

`Simulation.summary()` → `Metrics.summary()` 가 매 실행 종료 시 다음을 반환:
`ticks, alive, deaths, mean_survival_ticks, action_counts,
gather_by_resource, wealth_gini, world_resources, roles`.

## 로깅과 분석 파이프라인 (확장)

- 현재: 콘솔 요약(예제) + `summary()` dict.
- v0.3+: 틱별 이벤트를 JSONL 로 저장(거래·대화·제안 로그) → 사후 분석.
- 분석 노트북: 가격 수렴 곡선, 신뢰 그래프, 역할 타임라인 시각화.
- 반드시 **LLM 실행과 베이스라인 실행을 쌍으로** 저장하여 대조 검정에 사용.
