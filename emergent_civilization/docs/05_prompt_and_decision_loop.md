# 05. 프롬프트와 의사결정 루프 (Prompt & Decision Loop)

> 이 문서는 실험의 무결성이 가장 취약한 지점이다. 프롬프트에 무엇을
> 넣느냐가 곧 "무엇을 프로그래밍했느냐"이다.

## 의사결정 한 사이클

```
build_observation(부분 시야)          # sim/observation.py
        │  dict
        ▼
LLMPolicy.build_prompt(obs)           # 페르소나 + 지시 + 관찰(JSON)
        │  prompt(str)
        ▼
LLMBackend.complete(prompt)           # RunPod / NVIDIA / Echo
        │  text
        ▼
parse_action(text) -> Action          # 관대한 JSON 파싱, 실패 시 idle
        │
        ▼
ActionExecutor.execute(agent, action) # 규칙 적용, 결과 피드백
```

## 프롬프트 구성 (3부)

1. **지시(SYSTEM_INSTRUCTIONS)** — 세계의 물리와 출력 형식만 기술.
   생존 방식, 사용 가능한 행동, 그리고 "*협력·거래·신뢰·규칙 제안이
   유용할 수도 있으나 강제되지 않는다*"는 **가능성의 언어**만 담는다.
2. **페르소나** — 이름, 목표, 4개 성격 수치.
3. **관찰(JSON)** — 자기 상태, 인접 노드/에이전트, 최근 기억.

실제 문자열은 `sim/policy.py: SYSTEM_INSTRUCTIONS` 및 `LLMPolicy.build_prompt`.

## 금지 목록 (편향 유발 어휘)

프롬프트/관찰 어디에도 다음을 넣지 않는다:

- ❌ 직업명: "너는 나무꾼/상인/농부다"
- ❌ 가격·화폐 개념: "1 나무 = 2 식량", "돈"
- ❌ 제도 지시: "법을 만들어라", "세금을 걷어라"
- ❌ 사회 목표 주입: "번영하는 문명을 건설하라"
- ❌ 협력 강요: "다른 이들을 도와라"

허용되는 것은 오직 **생존 압력 + 가능한 행동 + 부분 관찰**이다. 사회는
이 최소 조건에서 나와야 한다. (→ `01_research_design.md` 편향 통제)

## 출력 계약과 견고성

- 모델은 단일 JSON 행동을 반환:
  `{"action": "...", "args": {...}, "reason": "..."}`.
- `parse_action` 은 잡담이 섞인 출력에서도 JSON 블록을 추출하고,
  파싱 실패 시 `idle` 로 폴백한다 → **한 번의 잘못된 응답이 시뮬레이션을
  중단시키지 않는다**.
- 미구현 마일스톤 행동을 반환하면 `ActionExecutor` 가 사유와 함께 거부하고,
  그 사유가 다음 틱 관찰의 기억에 남아 에이전트가 학습한다.

## 컨텍스트/비용 관리 (확장 대비)

- 관찰은 부분적이고 최근 기억 6개만 포함 → 프롬프트 크기 상한.
- v0.6: 오래된 기억을 요약 계층으로 압축.
- 100+ 규모: (a) 매 틱 전원 추론 대신 서브샘플링/이벤트 트리거 결정,
  (b) 백엔드 배칭·비동기 호출, (c) 소형 모델 + 선택적 대형 모델 라우팅.

## `reason` 필드의 연구적 가치

행동의 `reason` 은 실행에 영향을 주지 않지만 로그로 보존된다. 이는
"에이전트가 *왜* 협력/거래/규칙 제안을 했다고 스스로 말하는가"를 사후
분석하는 정성적 데이터가 된다. 창발 현상의 서사적 증거로 활용한다.
